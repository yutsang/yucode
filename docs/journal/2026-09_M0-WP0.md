Eighteen commits, `40fb5d4` through `6d6a4a2`. The Python harness was
described, measured, tagged, backed up and deleted; the measurements were
reviewed three times and corrected; and the TypeScript package was scaffolded
and verified green on Linux and Windows.

Everything is pushed. `python-final` is `6abc9e1`.

## 2. M0: freeze the Python before deleting it

Commits `40fb5d4` through `6abc9e1`. The ordering constraint drove everything:
`tests/golden/` is the only oracle M1 to M3 have, and once Python leaves this
Mac and the company box, the numbers cannot be recovered. Documentation can be

### 2.1 The plan did not survive verification

Reading the tree and the machine before starting found fourteen claims in the
plan that did not hold. Five changed an acceptance criterion:

- There is no `coding_agent/__main__.py`, so `python -m coding_agent` was never

- `show-config` has no `--output-format` flag. It is registered with no

in §7 below, because measuring them properly took two more passes.

The corrections went into `docs/REWRITE_PLAN.md` as a §0.0 section that wins
over the plan body. The body was left unedited: its reasoning is why each work

## 4. Three review rounds

Nothing produced in M0 had been looked at twice. Three reviews ran against the
backup, each with a different question.

### 4.1 What the goldens recorded wrong

Commit `ea77afe`. Ten capture bugs, each verified by re-running the code
before being fixed.

Three were projections losing information:

- `_xfrm` looked only for `a:xfrm`, which a `p:graphicFrame` does not have, so
  every rebuilt table recorded `xfrm: null`. That is precisely the field
  `fill_pptx_table` restores from the shape it replaced, so the projection was
  blind to the thing it existed to check.
- `_shape_text` concatenated runs across paragraphs, so a two-paragraph cell
  projected as `"ab"`, indistinguishable from one paragraph. Adding the
  separator revealed a Python bug the projection had been hiding:
  `write_pptx` leaves an empty first bullet when a slide has `bullets` and no
  `body`.
- `_error_envelope` structured only the "Available shapes" message, leaving
  `image_read`'s suffix allow-list as a bare Python `repr(list)` for a port to
  imitate.

Two cases did not test what they claimed. The single-period PDF case never
passed `periods`, and auto-detection needs two year tokens, so it recorded a
not-found instead of the single-centre band rule. The Stages fixture hid a
data row below the basis row, where skipping it changes nothing; the date row
is hidden now, so a port that iterated visible rows would fail to find it.

The hidden-column-range quirk sat on the sheet twelve other cases read, so the
manifest's claim that one case was expected to differ was wrong by a factor of
twelve. It moved to a sheet of its own.

The round also found nine defects that belong to the Python rather than the
capture. They are corrections 17 to 25. The sharpest:
`fill_pptx_shape_text` sets `run.font.name`, which writes `a:latin` only, so
the CJK typeface never applies in PowerPoint — while
`estimate_pptx_text_capacity` measures with Microsoft YaHei. Capacity and
rendering disagree on exactly the decks this harness exists for.

### 4.2 What the summary claimed wrongly

Commit `b2dac27`. Eighteen errors in 1,351 lines. Four would have changed the
port.

The worst: `bash_validation.py` was labelled DEAD in three places, including
the do-not-port list. It is not. `check_bash_safety` imports
`check_sed_in_place` and `check_path_traversal` from it and runs both as the
last two entries of its check list, on every bash call. A port following the
old text would have deleted two live safety checks and noticed nothing. Only
the classifier is unused.

The permission decision order was written as "deny first". `allow` mode
returns before any rule is read, so a deny rule cannot fire there. The claim
that read-only mode denies every bash command needed two qualifications as
well: an allow rule matching the whole command still gets through, and the
enforcer only knows a tool's permission because the runtime seeds it — built
without that seeding it treats everything as `danger-full-access`.

The eval baseline's ten failures were described as all one criterion. Eight
are tool-call budget; the other two are A1 and A3 answering having read no
file at all.

Two MCP presets ship, not one: `finance` still points at the server §21 drops.

Twelve citations were a few lines off. One of them, the per-tool-call anchor,
pointed at an unrelated line.

### 4.3 What the capture scripts did wrongly

Commit `3f98dff`, and the most valuable of the three. It reviewed the scripts
rather than their output, and found that the oracle was machine-specific and
time-dependent in ways `check_all.py` could never report locally.

Every one of these reproduced perfectly on the machine that captured it:

- **A timer.** The memory index marks an entry stale once it is 30 days old,
  and `discover_project_context` reads `date.today()`. Both prompt goldens and
  their sha256 would have started changing on 2026-10-12 and then changed
  every day.
- **Fonts that could not be rebuilt.** fontTools re-stamps `head.modified`
  during `save()` unless told not to, after `_freeze_head_dates` had zeroed
  it. The committed subsets carried a wall clock, two builds nine seconds
  apart differed, and `SOURCES.json`'s `output_sha256` was a one-shot value.
  Anyone re-running `vendor-fonts` to audit the subsets got a different hash,
  and `_verify_against_sources` then refused every capture. An unfixable loop
  around the foundation of the text metrics.
- The rendered prompt embedded `Darwin 25.6.0` and hashed it.
- `state_layout.json`'s live check hashed this machine's per-user temp
  directory, in the one file whose own note promised machine independence.
- The git fixture inherited `~/.gitconfig`, where `core.abbrev`,
  `diff.noprefix`, `diff.context` or `core.excludesFile` each rewrite the
  captured diff and `commit.gpgsign` kills the capture outright.
- The office `Normalizer` never tried the JSON-escaped spelling of a Windows
  path, so on Windows the operator's username would have gone into
  `scrubbed_sha256` for every case whose output names a file.
- `discover_instruction_files` walks every ancestor of the workspace looking
  for thirteen filenames. On Windows the temp directory sits under the user's
  home, so a developer with `C:\Users\<name>\CLAUDE.md` would have captured
  their own private instructions into the golden.
- The harness `--check` intersected expected with produced, which made the
  "no longer produced" branch unreachable: a capture that silently stopped
  writing an output stayed green.
- The office `check` compared parsed JSON, so a change to `_write_json` would
  rewrite every byte while reporting a match.

The font measurement also covered only 58 of the 95 printable ASCII glyphs,
because it measured the characters the cases happened to use while the subsets
contain all of them. Measuring the full set brought the Arial mismatch list to
exactly the 21 glyphs the docstring had always claimed. Four of them had no
oracle at all.

Five behaviours had notes but no coverage and now have cases: the numeric
branch of `read_excel_preview`'s type inference (every column sat at 2/3
truthy-numeric, under the 0.7 threshold, so a port hard-coding `"text"` passed
all of them), `excel_to_json`'s `col_{i}` fallback, a negative layout index,
the autofit `fontScale` formula, and the progressive-fill contract the tool's
own description promises. That last one also gave `pre_steps` its first user;
the mechanism had been sitting in the runner with no case behind it.

### 4.4 The lesson

A golden's most dangerous bug reproduces perfectly on the machine that
captured it. A green `check` on one box says nothing about whether the oracle
means anything on another, and nothing about whether it will still mean
something next month.

`tests/smoke.test.ts` now asserts that no golden carries a path from the
machine that captured it. All four of its patterns were real findings.

## 5. WP0: the scaffold

### 5.1 Authored blind

Commit `bab4f1f`. `package.json`, `tsconfig.json`, `.npmrc`,
`eslint.config.js`, `scripts/check-no-binaries.mjs`, both launchers, a CLI
stub, a smoke test, `docs/ARCHITECTURE.md` and a rewritten `AGENTS.md`. None
of it ran: Node here was 21.7.1, which predates type stripping.

Two decisions in it are worth knowing before changing anything.

The tsconfig pairs `erasableSyntaxOnly` with
`rewriteRelativeImportExtensions`, so a relative import is written with its
`.ts` extension, runs directly under Node's type stripping with no build step,
and is rewritten to `.js` on the way into `dist/`. That is what lets
`node --test` execute the sources while `yucode.cmd` runs a compiled tree. The
cost is that enums, namespaces, parameter properties and `import x = require()`
are unavailable.

eslint carries the layering rule as an error: nothing under `src/runtime`,
`src/tools`, `src/provider` or `src/session` may import from `cli`, `tui`,
`bridge`, `server` or `plugins`. Four consumers drive the same loop, and one
convenience import inside a tool ends that property with nothing else in the
build complaining.

Writing `check-no-binaries.mjs` turned up its first finding before it ran.
**TypeScript 7 cannot be used.** 7.x is the Go-based native compiler, and
`typescript@7.0.2` lists twenty `@typescript/typescript-<platform>` packages in
`dependencies` as well as `optionalDependencies`, so `omit=optional` does not
exclude them and a plain `npm ci` installs a native binary. The pin is 6.0.3,
verified as having no dependencies at all. Correction 30 records it with the
general lesson: the exclusion list is not static, and a major bump needs
`npm view typescript@<version> dependencies` rather than an assumption.

### 5.2 Then run

Commit `c19d61f`. Node 24.21.0 installed keg-only, so nothing on PATH changed
and the 2024 `.pkg` is untouched. Four things were wrong and none would have
been visible by reading:

- `rootDir: "."` put the entry point at `dist/src/cli/main.js` while both
  launchers hard-code `dist/cli/main.js`. One tsconfig cannot both type-check
  tests and emit a tree rooted at `src`, so it is now two.
- The eslint scripts override replaced `disableTypeChecked`'s
  `languageOptions` instead of extending them, which is what asks a plain
  `.mjs` file for a tsconfig project it is not in.
- `parameter-properties` was configured with a value the rule does not accept,
  so eslint refused to start rather than reporting a lint error.
- `no-floating-promises` fires on every `test()` call, because `node:test`
  returns a promise callers are not meant to await. Naming it under
  `allowForKnownSafeCalls` keeps the rule live inside test bodies.

`dist/` still held the Python wheel and sdist from before the reset.
Gitignored, so never committed, but sitting there.

### 5.3 Windows

Commit `6d6a4a2`. The first CI run was green on ubuntu and failed on
windows-latest at the last step, and `npm test` had passed there, so glob
expansion and path handling were fine. The log showed
`node dist/cli/main.js version` printing nothing at all.

The guard was `import.meta.url === \`file://${process.argv[1]}\``. On Windows
`argv[1]` is `D:\a\...\main.js` while `import.meta.url` is
`file:///D:/a/.../main.js`, so the two are never equal, `main()` is never
called, and the process exits 0 having done nothing. Silent, and green on
every machine anyone would develop on. The comment above it claimed the url
comparison was the portable one.

`import.meta.main` is exactly this predicate and is available on Node 24.

The more useful half of the fix is the test. Calling `main()` directly cannot
reach the guard, so no unit test could have caught it — only a CI step on an
OS nobody runs locally. The smoke test now spawns
`node src/cli/main.ts version` as a subprocess, which exercises the guard
wherever `npm test` runs, on the sources and with no build step. Anything else
that only runs as a script needs the same treatment, and `AGENTS.md` says so.

## 7. The two measurements that changed the M3 design

Both were asserted in the plan from reading, corrected once from a review, and
corrected again from measuring properly.

**Font advances cannot be computed.** Pillow here has no raqm, so it runs
`Layout.BASIC` and `getlength` loads each glyph with `FT_LOAD_DEFAULT`: every
advance is grid-fit to a whole pixel by the TrueType interpreter. On Arial at
9 pt, 21 of the 95 printable ASCII glyphs have a hinted advance that
`round(hmtx)` gets wrong — `C D F H J M N R T U W Z c k m s v w x y z`. No
rounding rule fixes all 21 without breaking the other 74, so `fonts.ts` has to
ship the measured table.

The plan's §5 had assumed `fonts.ts` could reproduce the FreeType integer
pipeline from fontkit's font-unit advances. The first review said 13 glyphs;
direct measurement said 21; and the first measurement said 17, because four of
the glyphs were never measured at all.

Two qualifications came out of measuring it properly, and they change how the
goldens should be read. The divergence belongs to the font rather than to
hinting: the vendored Noto Sans subset has zero mismatches over the same 95
glyphs, so the portable pass alone cannot catch a port that computes advances
by rounding. The system pass can, and Arial is what the target box resolves.
CJK is clean either way, because CJK advances are uniform-width and land on
integers.

**`databook.xlsx` cannot be built with openpyxl.** Four of the features the
fixture needs are unreachable through it: a formula's cached `<v>` comes out
empty, `CellRichText` round-trips as `inlineStr` and never reaches
`sharedStrings.xml`, floats go through `"%.16g"` so `0.30000000000000004`
cannot be expressed, and `column_dimensions.group()` injects an
`outlineLevel`. The fixture is hand-assembled OOXML, following the precedent
already in the repo for PDFs.

## 8. Tried and abandoned

**`git rebase --exec` for the email rewrite.** It replayed five of the eight
commits correctly and then stopped at step 13 of 16, with no conflict, nothing
staged, nothing unstaged, and the scaffold commit neither applied nor
reported as empty. The reason was not determined. `git rebase --abort`
restored cleanly and `git filter-branch --env-filter` over `origin/main..HEAD`
did the whole range in one pass, content byte-identical to a backup ref,
author dates preserved, and `python-final` untouched because it sits below the
rewrite base.

`refs/heads/backup-before-email-rewrite` and `refs/original/refs/heads/main`
are still in the local repository, pointing at the pre-rewrite commits. They
are safe to delete now that everything is on `origin`.

**A 400-byte cap for the truncation golden.** Chosen so the recorded rows
would stay readable. It put two rows below the caller's guard, recording a
state production cannot reach, and `_MIN_LEAF_CHARS` is 500, so no string leaf
was ever long enough to shrink and the `_shrink_json_strings` path — the whole
reason the truncator is not a byte slice — went untested. Captured at the real
32768 now, as digests plus head and tail rather than 32 KB of filler.

## 9. Operational notes

**Node.** 24.21.0 at `/opt/homebrew/opt/node@24/bin`, keg-only, PATH not
changed. `/usr/local/bin/node` is still the 2024 `.pkg` at 21.7.1. Prefix
every npm or node command:

    export PATH="/opt/homebrew/opt/node@24/bin:$PATH"

**A keg-only Node can break from an unrelated brew upgrade.** On 2026-10-26,
five weeks after it was installed, `node` died with
`Library not loaded: libsimdjson.33.dylib`: Homebrew had moved `simdjson` to
5.0.3 and the `node@24` bottle was linked against `.33`. `brew reinstall
node@24` repairs it and picks up whatever 24.x is current. Nothing else was
affected — `check_all.py` runs on python3, and CI had stayed green the whole
time — but every npm command fails until it is fixed, and the error says
nothing about Node being the problem.

**Pushing.** The GitHub account blocks command-line pushes that expose the
real address, so author and committer must both be
`19373417+yutsang@users.noreply.github.com`. The repository's local
`git config user.email` is set to it, so new commits are correct automatically.
History at and below `6abc9e1` still carries the old address and is not being
changed.

**Checking the goldens.**

    git archive python-final | tar -x -C _legacy_python   # if absent
    python tools/golden/check_all.py

`_legacy_python/tools/golden/` is the copy that was current at the tag. It is
stale — the review rounds changed six of those files — and the tree's copy is
the one to run.

**The capture scripts need Python, not Node.** They import the package they
measure. `check_all.py` fails with instructions if `_legacy_python/` is
missing.
