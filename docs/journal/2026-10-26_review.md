## Native-file scanner

[M] A synthetic `node_modules/fixture/tests/payload.exe` passed the old
scanner. The same file at the package root failed. Test, documentation and
example directories were excluded by name, although the deployment rule
applies to every shipped file.

[M] A file starting with `MZ` also passed when named `payload` rather than
`payload.exe`. The scanner checked extensions only.

The scanner now visits every real directory and checks file headers for DOS/PE,
ELF, Mach-O (including universal files), and static archives, as well as the
existing extension and manifest checks. Directory read errors propagate
instead of silently omitting part of the scan. It reads at most eight bytes
per file for header detection. Regression tests invoke the actual script in
isolated dependency trees and cover both failures, misleading extensions, and
allowed JavaScript, JSON and WebAssembly.

A second pass found that linked packages and malformed manifests could also
escape the audit. Directory symlinks and Windows junctions now lead into the
scan, with canonical directory paths preventing cycles and duplicate walks.
Broken links and malformed manifests produce findings. Tests cover linked
packages with a cycle, invalid JSON and non-object manifests, native build
metadata, and platform-specific optional dependencies.

This remains an unpacked-file check; it does not inspect compressed archives.
Header signatures are conservative checks, not a complete executable parser.
A passing scan also does not establish that the target machine's EDR accepts
WebAssembly.

## Failure reporting and network diagnosis

[M] A DNS lookup of the configured provider and a public control domain
(`example.com`) both failed with `gaierror` errno 8. No HTTP/HTTPS proxy
environment variable was set. This supports an execution-environment DNS
problem rather than a provider-specific conclusion. No endpoint, DNS or proxy
settings were changed.

The golden aggregate checker previously labelled every nonzero subprocess
exit `DRIFT`, including an import failure from a missing dependency. It now
uses `FAIL` and says the checks failed, preserving their stdout/stderr so the
underlying cause can be diagnosed. A failed check alone does not establish
that the oracle changed.

The repeatable single-mode procedure now lives in `docs/EVAL_BASELINE.md`.
It covers a frozen in-memory config, isolated legacy state, independent source
snapshot, output validation and human review. Its live run remains unverified
while DNS is unavailable; offline configuration injection was checked against
the frozen implementation without instantiating a runtime or provider.
